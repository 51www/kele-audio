### 全局开发约定（各里程碑通用）

1. 每个里程碑开始前先过一遍对应的"准入条件"，不满足不开工；
2. 每个里程碑结束时跑一遍"准出条件"清单，全过才算完成；
3. 发现 B 站接口行为与本文档假设不符时，先更新 `docs/PRD.md` 风险章节再继续；
4. Git 约定：每个里程碑一个分支（`feat/m2-play-core`），准出后合并主干打 tag（`m2`、`m3`…）。

## M0 技术验证（Spike）

> **目标**：用最小代价验证"地基"是否成立。全部通过才进入正式开发；任一项不通过，先回到方案调整，禁止带病开工。

**产出物**：一个独立的最小 Demo 工程（或命令行工具）+ 一份 `docs/spike-report.md` 验证报告。

| # | 验证项 | 方法 | 通过标准 |
|---|---|---|---|
| S1 | WBI 签名搜索接口 | 匿名调用搜索接口（关键词"有声小说""相声"） | 稳定返回结构化结果，无 -412/403 |
| S2 | 分 P 列表 + DASH 音频流 | 取一个多 P 视频的 `pagelist` → `playurl`（fnval=16） | 拿到 m4a 流地址并在 Android 真机播放成功（重点验证 Referer/UA 问题） |
| S3 | 播放地址有效期 | 记录取址时间，隔 1h/2h/4h/8h 尝试播放同一 URL | 明确实测有效期时长，写入报告（影响 R5 策略） |
| S4 | 后台播放 + 续播 Demo | `just_audio` + `audio_service` 最小实现 | 锁屏可控制；杀进程重启后回到原进度 |

**风险提示**：S1/S2 若遇 -412，先补齐请求头与 Cookie（buvid3），降低请求频率再试。

**预估**：3 天。

> **M0 实际结果（2026-10-23）**：按 `docs/reference-abts.md` §4 降级为移植冒烟测试。
> S1 ✅ PASS · S2 ✅ PASS（接口层；真机播放移交 M2）· S3 🚧 120min + T+14min（长周期待补）·
> S4 ⏸ 待真机。详见 `docs/spike-report.md`。判定：**接口地基成立，不阻塞 M2 开工**。

## M2 播放核心（关键路径）

> **目标**：把"专辑 → 章节 → 地址 → 播放 → 进度持久化"整条链路做扎实。这是全项目质量的底座，M3/M4/M6 都踩在它上面。

### 任务清单

> 8 项任务 2026-10-23 全部落地（详见 `.logs/milestone-2.md` 第一节）。

1. **领域模型**
   - `Album` / `Chapter` 实体（PRD §7.5），章节来源抽象为"多 P"与"合集/系列"两种 source_type。
2. **API：播放地址服务**
   - DASH 播放地址获取（fnval=16），支持 64k/132k/192k 音质选择；
   - **URL 不落库**，只存内存；封装"取址 → 播放"入口。
3. **播放器服务（`core/services/player`）**
   - `just_audio` 封装：播放/暂停/seek/倍速/切章；
   - 播放模式：顺序/列表循环/单曲循环。
4. **地址失效自愈（R5 / P-05）**
   - 监听播放错误（403/超时）→ 静默重取地址 → seek 回原进度续播；
   - 弱网/断网切换场景处理。
5. **后台与系统集成（P-01/P-02/P-06/P-07）**
   - `audio_service` 前台服务 + 锁屏/通知栏控制；
   - 音频焦点（来电/导航打断）；
   - 耳机/蓝牙线控。
6. **进度持久化（P-03/P-04）**
   - 播放中每 15~30s 写 `play_history`；
   - 章节切换、暂停、退出时立即写盘；
   - 冷启动恢复：最近播放的专辑/章节/进度。
7. **播放页 UI（PRD §5.4）**
   - 封面、进度条拖拽、控制区、倍速面板、定时关闭面板、章节列表抽屉、加入书架按钮。
8. **倍速与定时关闭**
   - 倍速 0.5x~3.0x，持久化（开放问题 Q3 采纳）；
   - 定时关闭：5/10/…/60 分钟/本章结束。

### 准出条件（对应 PRD §5.4 P-01~P-08，逐条实测）

> 2026-10-26 核对：**P-01~P-08 全部通过**。
> P-03/P-04/P-05/P-08 浏览器实测（截图 `docs/shortscreen/m2-*.png`）；
> P-01/P-02/P-06/P-07 真机实测（OPPO PKC110 / Android 17，截图 `docs/shortscreen/m2d-*.png`，清单 `.logs/m2-device-checklist.md`）。

- [x] P-01 后台播放：切后台/锁屏不断音 —— ✅ 真机：灭屏 60s 进度推进 67s、前台服务存活、`state=PLAYING` 持续；
- [x] P-02 锁屏通知展示与控制 —— ✅ 真机：通知 `channel=…channel.audio` / `category=transport` / `actions=3` / `FOREGROUND_SERVICE`；锁屏媒体卡 uia dump 确认（`m2d-08-lockscreen-uia.xml`）；
- [x] P-03 杀进程重启 → 回到原进度（误差 ≤ 5s）—— ✅ reload 实测：恢复同章节，续播 Range 精确到原进度；
- [x] P-04 跨章续播：重进专辑定位到"最后听的章节"—— ✅ 实测：恢复第 04 章 + 抽屉高亮 + 切章取新 cid 续播；
- [x] P-05 手动把内存中的 URL 改坏模拟过期 → 自动重取并续播 —— ✅ 实测：演练菜单作废地址 → 自动重取 playurl → 原进度无中断续播；
- [x] P-06 蓝牙耳机按键控制正常 —— ✅ 真机：`keyevent 85/87/88` 播放暂停、切章、`>5s` 重播本章均正确，日志确认媒体键路由到我方 session；**物理耳机实按留 M7**（无耳机硬件），`media dispatch` 该 ROM 不可用；
- [x] P-07 播放中触发导航语音 → 音频压低/暂停并恢复 —— ✅ 真机：`interrupted`（相机录像 GAIN_TRANSIENT 抢占 → 暂停 → 释放后自动续播）、`ducked`（语音助手 MAY_DUCK → 不中断）、`lost`（永久抢占 → 暂停不自动恢复）；`noisy` 受保护广播无法注入且无耳机，由 4 个单测 + 原生 receiver 代码覆盖；
- [x] P-08 定时关闭到点停止；倍速重启后保留 —— ✅ 实测：1.25x reload 保留、定时全档 + 本章结束生效（到点暂停有单测）。

**开发期修复的缺陷**：紧凑栏下标越界断言（动态计算）、release 资源收缩剔除 audio_service 图标（`res/raw/keep.xml` 保活）、**音频焦点五事件回调从未接线**（补 `_bindFocus`/`_restoreVolume` + `dispose` 清理）、锁屏进度按 1.0 倍速外推（`MediaSnapshot.speed` 传真实倍速）。

**风险提示**：本里程碑是 R5/R6 的集中消化点，若国产 ROM 后台限制导致音频中断，需在通知渠道/前台服务类型（`mediaPlayback`）上排查。—— 真机 OPPO ROM 实测未出现该问题。

**预估**：5 天。
